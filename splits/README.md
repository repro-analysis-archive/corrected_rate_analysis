# Split assignments and cohort definitions: regenerable, not distributed

No patient identifier is distributed in this repository. The fixed development/evaluation split, the sequential
5-fold partition, the enrolment-epoch assignment and the cohort membership are all **regenerated deterministically
from the public MAMA-MIA clinical workbook** by the released code and seeds, and verified with the digests in
`SPLIT_DIGESTS.json`. A user who has downloaded the source data reproduces the identical sets; a user who has not
learns nothing about individual patients from this folder.

| set | regenerated by | rule |
|---|---|---|
| HER2-negative cohort (739) and HER2-positive cohort (241) | `src/rate_analysis/r4_stageA.py` (`load`), `src/features/cohort_ids.py` | workbook rows with `dataset == "ISPY2"`, `her2 == 0` or `1`, non-missing `pcr`, in workbook row order |
| H1 / H2 split (370 / 369) | `src/rate_analysis/r7_common.py` (`split_739`), written by `fit_priorities.py` | `numpy.random.default_rng(42).permutation(739)` over the analysis-frame order (the cohort order above, preserved through the loader's inner merges); the first 370 permuted indices form H1, the remaining 369 H2; outcome and treatment not used; no stratification |
| sequential 5-fold partition | `src/rate_analysis/build_Z.py` | `numpy.random.default_rng(42).permutation(739)` split into five nearly equal folds with `numpy.array_split` |
| enrolment epochs (22 levels, 980 patients) | `src/rate_analysis/derive_epochs.py` | boundaries at the first observed acquisition date and the day after the last observed date of every experimental arm (all `nac_agent` values except the control arms `Paclitaxel` and `Paclitaxel + Trastuzumab`); populated intervals numbered chronologically (`config/epoch_canonical_mapping.json`) |
| empty-arm-epoch exclusion set (11 patients) | epochs 1 and 21 of the table above (`config/empty_arm_epochs.json`) | the two epochs in which no experimental-arm patient was observed |

The deterministic preprocessing on which the split depends is the workbook row order; the digests are therefore
conditional on the workbook version, whose sha256 is recorded in `SPLIT_DIGESTS.json` and
`checksums/INPUT_PROVENANCE.txt`.

## Verification

```bash
bash scripts/run_pipeline.sh analysis        # or at least: derive_epochs.py, fit_priorities.py, build_Z.py
python scripts/verify_split_digests.py       # compares the regenerated sets with SPLIT_DIGESTS.json
```

`SPLIT_DIGESTS.json` holds, for each set, its size and the SHA-256 of the sorted, newline-joined identifier list
(no trailing newline, UTF-8), plus the sha256 of the regenerated epoch table file. On the platform of the record the
regenerated split, partition and epoch table reproduced the frozen files exactly.

## Row labels of the derived data

The per-patient files under `derived_data/` are labelled by position instead of identifier: `h2_row` is the
position within H2 (1 to 369) and `h1_row` the position within H1 (1 to 370), both in analysis-frame order;
`fold_row` is the position within a sequential fold. After regenerating the split, the position of every patient
follows from `reproduction/rate_primary/split_739.csv` (row order = analysis-frame order), so regenerated and
released per-patient files align row by row.
